Problem statement
Google Workspace SMEs hold project commitments across scattered Docs and Sheets — customer targets in one file, QA forecasts in another, security sign-off in a third. Nothing reconciles baseline vs forecast vs commitment vs approved decision, so teams risk promising dates the evidence does not support.

All organizations, people and records in this deck are fictional synthetic data. Results are reported as measured.

1
Brief about the idea

An evidence catalog that answers with sources, dates and honest gaps

KnowBridge is a grounded search and decision-support tool for Google Workspace SMEs. It imports a bounded set of files, keeps the original text and record dates attached to every piece of evidence, and answers questions with literal, click-through citations — reconciling conflicting documents instead of hiding them.

The workflow

Connect → Investigate → Reconcile → Decide — inside the tools teams already use, with every answer traceable to source text.

The output

A structured Decision Brief: options, risks, unknowns and conditional recommendations — for a human to verify. Never an autonomous decision.

The discipline

When evidence is absent, the answer is "insufficient evidence". Fabricated excerpts are rejected server-side; a later forecast never silently erases an earlier commitment.

The proof

Deployed on Google Cloud with a deterministic synthetic corpus and a 12-case live benchmark. Failures are reported as measured, including service errors.

Opportunities

Why KnowBridge is different — and how it solves the problem

  • How is it different from existing ideas?  Enterprise search returns passages. KnowBridge types evidence (baseline / forecast / commitment / approved decision), preserves each document's recorded date, and surfaces conflicts across files instead of flattening them into one answer.
  • How does it solve the problem?  One question replaces file archaeology: grounded retrieval → literal citation verification → temporal and conflict analysis → a decision brief with explicit unknowns. Grounding gates run before and after the model; if they fail, the answer is withheld (fail-closed).
  • USP of the proposed solution  Temporally aware, explainable decision support: a revised forecast does not erase a customer commitment, "pending" is never shown as "approved", and every quoted excerpt must literally exist in an authorized source — verified server-side, not just prompted.

Market framing is stated as a testable hypothesis (Singapore services SMEs on Google Workspace) — not a validated market claim.

List of features offered by the solution

Features

  • Bounded Workspace import — Google Picker + OAuth; registered fictional files only; Sheets import first tab.
  • Source catalog — every record with stable ID, owner, recorded date and full original text.
  • Grounded Ask — answers with literal, click-through citations to exact excerpts.
  • Abstention — absent evidence is reported as "insufficient evidence", never invented.
  • Temporal & conflict analysis — baseline vs forecast vs commitment vs approved decision, typed.
  • Decision Brief — options, risks, unknowns, conditional next steps for human review.
  • Save & review briefs — authorized member sessions; revocation-checked Firebase ID tokens on mutations.
  • Effective-date discipline — document effective date is distinguished from any Drive updated timestamp.
  • Tenant isolation — retrieval is restricted to authorized tenant/user documents before the LLM is called.
  • Fail-closed integrity gates — fabricated excerpts, missing citations or coverage gaps block the answer.

Process flow diagram

Use-case flow: connect → investigate → reconcile → decide

1 · Connect

Member selects registered files via Google Picker (OAuth). Only authorized, tenant-pinned sources are imported and indexed.

▸

2 · Investigate

Ask a question. Tenant-scoped retrieval + grounded answer with literal excerpts and source links. Absent evidence → abstain.

▸

3 · Reconcile

Temporal & conflict analysis across sources: what is baseline, forecast, commitment, approved decision — and since when.

▸

4 · Decide

Generate a Decision Brief (options, risks, unknowns) for human review. Saved for review; never auto-approved.

Grounding gates on every answer: tenant-scoped retrieval → literal citation verification → decision-coverage check → semantic review → fail closed (502/503) if any gate fails.
Actors: SME project lead / delivery owner (asker) · authorized Workspace member (imports, reviews briefs) · human decision-maker (approves — the app never does).

Architecture diagram of the proposed solution

Google Cloud architecture — fail-closed grounding

Google Workspace

Docs / Sheets (fictional). Google Picker + OAuth for selected-file import. Document effective dates travel with the content.

▸

Cloud Run · asia-southeast1

Next.js / Node 22 API. Non-root container, Secret Manager, CSP. Grounding gates; revocation-checked Firebase ID tokens on mutations; fail-closed 502/503.

▸

Gemini + Firestore

gemini-3.8-flash (global endpoint) for answers & briefs; gemini-embedding-001 768-d vectors (us-central1); Firestore vector retrieval, tenant-scoped.

Answer pipeline

Tenant-scoped retrieval → model call → literal citation verification → decision-coverage check → semantic review → ship or fail closed.

Security basics

Non-root container · Secret Manager secrets · revocation-checked tokens on writes · CSP · synthetic-tenant pinning · cross-tenant chunks never reach the LLM.

Honest disclosure: model processing is not Singapore-only (Gemini global endpoint; embeddings US). Real-data import is prohibited.
